# TempSystem

WPF-приложение для мониторинга и управления температурной системой через Modbus TCP. Цель внешнего контура — поддерживать заданную температуру системы с допуском ±0,2 °C.

## Сборка и запуск

Требуются Windows и .NET 10 SDK. При первой сборке зависимости NModbus и WPF-UI восстанавливаются из NuGet.

Из корня репозитория приложения:

```powershell
dotnet build
dotnet run --project TempSystem/TempSystem.csproj
```

В отдельном терминале, из каталога для проектов, запустите эмулятор:

```powershell
git clone https://github.com/AcademVac/ModbusEmulator.git
cd ModbusEmulator
dotnet run --project ModbusEmulator/ModbusEmulator.csproj
```

В приложении укажите IP и порт сервера (по умолчанию `127.0.0.1:21316`) и нажмите «Подключить». Подключение устанавливает уставку нагревателя 50 °C и включает ПИД. Задайте целевую температуру системы и нажмите «Запустить»; кнопка «Остановить» выключает ПИД и прекращает внешний контур, сохраняя опрос датчиков.

## Архитектура

`MainWindow.xaml` и `MainWindow.xaml.cs` отвечают за интерфейс, команды оператора, таймер опроса и состояние управления. `ModbusService` устанавливает TCP-соединение, читает и записывает регистры через NModbus, преобразует значения и сообщает о потере связи. Данные одного опроса передаются в модели `SystemState`; `TemperatureController` получает эту модель и целевую температуру, возвращая рассчитанную уставку нагревателя. Окно связывает компоненты: получает показания от сервиса, обновляет интерфейс, вызывает регулятор и передаёт его результат обратно сервису для записи.

Для небольшого приложения выбраны обработчики WPF в code-behind с вынесенными в сервисы обменом и расчётом. Синхронные Modbus-запросы выполняются через `Task.Run`, а флаг занятости предотвращает их одновременное выполнение; интерфейс обновляется в UI-потоке.

Для отрисовки графика используется библиотека из NuGet - LiveCharts2


## Алгоритм управления и коэффициенты

Используется каскадное управление: внутренний ПИД эмулятора регулирует температуру нагревателя, а внешний контур приложения регулирует `T_system`, меняя уставку этого ПИД. При каждом опросе по таймеру с периодом 500 мс приложение считывает температуры и рассчитывает уставку как компенсацию стационарных теплопотерь плюс пропорциональную коррекцию ошибки:

```text
C = (6.03 + 1.5) / (6.03 × 0.7) ≈ 1.784
Kp = 2.0
baseSetpoint = T_ambient + C × (T_target − T_ambient)
setpoint = round(clamp(baseSetpoint + Kp × (T_target − T_system), 20, 450), 1)
```

Коэффициент `C` получен из стационарного теплового баланса [модели эмулятора](https://github.com/AcademVac/ModbusEmulator/blob/f92cdc0ed50960eef127f62769ee4e6e57160dc4/ModbusEmulator/ThermalModel/ThermalSimulator.cs): теплоёмкостный расход воздуха `1.2 × 0.005 × 1005 = 6.03 Вт/К`, эффективность нагревателя `0.7`, теплопотери камеры `1.5 Вт/К`. Компенсация определяет необходимую уставку в установившемся режиме, а пропорциональная часть корректирует отклонение текущей температуры от цели. Отдельный интегратор во внешнем контуре не используется: статический режим учитывается моделью, внутренний ПИД уже содержит интегральную составляющую.

`Kp = 2.0` принят как исходная фиксированная настройка и проверен на модели; автоматическая оптимизация коэффициента не проводилась. Проверка текущего кода через Modbus TCP с ускоренным модельным временем подтвердила удержание ±0,2 °C для целей 50, 100 и 150 °C при окружающей температуре 20 °C. Это результат проверенных сценариев, а не гарантия для другой тепловой модели. Уставка округляется до 0,1 °C и записывается в Holding-регистр `0x0000` устройства Unit ID 5 в масштабе ×10; регистр `0x0001` задаёт режим ПИД (`0` — выключен, `1` — включён).

## Принятые допущения

- Цель относится к температуре системы, поэтому уставка нагревателя может быть выше неё. Начальная уставка 50 °C относится к нагревателю и включает ПИД до запуска внешнего контура.
- Цель ограничена диапазоном 15–150 °C; дополнительно проверяется нижний предел достижимой температуры. Эмулятор не имеет активного охлаждения; минимальная расчётная цель равна `T_ambient + (max(20, T_ambient) − T_ambient) / C` с допуском 0,2 °C. При окружающей температуре 20 °C цель 15 °C отклоняется.
- Рабочая уставка нагревателя ограничена 20–450 °C. При ошибке датчика или измеренной температуре системы ≥160 °C либо нагревателя ≥470 °C внешний контур останавливается и выполняется попытка выключения ПИД.
- Давление отображается, а ненулевой статус его датчика считается ошибкой. Диапазон 80–120 кПа трактуется как справочный: отдельного аварийного предела в задании нет, а модель при 150 °C даёт около 146,2 кПа.
- При потере связи опрос и внешний контур останавливаются, оператор получает сообщение. Без связи выключение удалённого ПИД гарантировать нельзя. Переподключение выполняется вручную, снова устанавливает 50 °C и включает ПИД; внешний контур запускается отдельной командой оператора.
- Период 500 мс считается номинальным: если предыдущий запрос ещё выполняется, следующий тик пропускается.
